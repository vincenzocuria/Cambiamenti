# Audit Sicurezza, Privacy e Qualità — Cambiamenti
**Data**: 8 ottobre 2026  
**Revisore**: Cloud Agent (analisi autonoma end-to-end)  
**Proprietario**: Vincenzo Curia  
**Ambiente live**: https://cambiamenti.vcuria.app  
**Repository**: https://github.com/vincenzocuria/cambiamenti (PUBBLICO)

---

## Executive Summary

Questo audit completo ha analizzato sicurezza, privacy (GDPR), accessibilità e qualità del codice del gestionale Cambiamenti, un sistema per la formazione professionale che gestisce dati personali di studenti (inclusi possibili minori), docenti e personale amministrativo.

**Rischi critici identificati**: l'email personale del superadmin è hardcoded nel codice pubblico. Il sistema permette caricamento e visualizzazione di file HTML (rischio XSS). Manca una gestione esplicita del consenso per minori e un'informativa privacy autonoma. Sono state trovate 5 vulnerabilità HIGH severity nelle dipendenze npm.

**Raccomandazione principale**: rimuovere dati personali dal codice, rendere privato il repository, implementare gestione consenso minori e informativa privacy completa, aggiornare dipendenze vulnerabili, rimuovere upload file HTML.

## Metodologia

Questo audit è stato condotto come segue:
1. **Analisi statica del codice**: lettura completa migrations SQL, edge functions, frontend (componenti, services, lib)
2. **Analisi cronologia git**: ricerca credenziali/secrets in tutti i commit con `git log -p`, `git log -S`
3. **Dependency audit**: `npm audit` per vulnerabilità note
4. **Code review sicurezza**: ricerca pattern XSS, injection, IDOR, CORS, auth bypass, info disclosure
5. **Code review GDPR**: verifica raccolta consenso, informativa, retention, data minimization, trasferimenti, diritti interessato
6. **Code review accessibilità**: controllo semantica HTML, ARIA, contrasto colori (spot check, non test automatici completi)
7. **Analisi infrastruttura**: lettura configurazioni Cloudflare/Supabase, secrets management

**Limitazioni**: Non sono stati eseguiti test di penetration testing attivi, nessun accesso a produzione con credenziali reali, nessun login, nessuna scrittura su database live, nessuna chiamata API Moodle/BBB di produzione. Tutti i findings sono basati su analisi statica e inferenza dal codice.

## Note finali

Il progetto ha un'architettura solida (React+Vite frontend, Supabase backend con RLS, Cloudflare Workers per hosting) e il codice è generalmente pulito. I problemi critici riguardano principalmente **gestione secrets/dati personali in un repository pubblico** e **compliance GDPR incompleta** (consenso minori, informativa, retention).

**Repository pubblico**: considerando che il sistema gestisce dati di studenti, molti dei quali potrebbero essere minori, insieme a documenti d'identità, IBAN, codici fiscali, email e password (criptate ma comunque sensibili), **si raccomanda fortemente di rendere privato il repository**. Un progetto gestionale di questo tipo non dovrebbe essere open source senza aver prima implementato misure di anonimizzazione dello schema e aver ottenuto valutazione legale sulla conformità alla pubblicazione.

**Azioni immediate**: rimozione dati personali (email superadmin) dal codice, repository privato, fix XSS HTML upload, aggiornamento dipendenze vulnerabili, implementazione consenso minori e privacy policy.

**Contatti per chiarimenti**: questo audit è stato generato autonomamente da un agente cloud. Per domande tecniche o legali, contattare il proprietario del progetto.
